## 0. 一句话结论

**本项目不缺算法种类，缺的是「优化」的三要件。**

| 侧 | 状态 |
|---|---|
| 知识 / 规则侧 | ✅ **工业界 Tier-1 厚度** —— expert 侧 **20/20 工艺算法物理化闭环** + fuzzy 侧 **1646 条规则** |
| 物理 / 解析侧 | ✅ **已完成**（13 份物理设计文档 / 20 个算法全绿，2026-07-05 路线图闭环） |
| 数据 / 学习侧 | ⛔ **空白** —— 45 条调优记录、**0 条质量标签** |
| 闭环 / 优化侧 | ⛔ **空白** —— 无目标函数、无 Pareto、无「下一轮试什么」 |

⇒ **演进的正确顺序：先补「标签 + 流程」，再谈「案例检索 / 代理模型 / 多目标优化」。**
反过来做（先上算法、后补数据）会得到一个训不出东西、也无法验证的模型。

## 2. 工业场景算法谱系（按工业界实际用法，非教科书）

### 族 1 · 知识 / 规则驱动

| 算法 | 工业界形态 | 本项目状态 |
|---|---|---|
| 专家规则表 | 模具厂工艺手册数字化 | ✅ `expert` 引擎 |
| 模糊推理 | 规则带「轻微 / 较明显」这类模糊档位时的标准解法 | ✅ `fuzzy` 引擎（1646 规则） |
| 派发表 Dispatching | 「尺寸 + 材料 → 参数模板」查表 | ✅ 规则表的另一种形态，已被 expert 覆盖 |
| **案例检索 CBR / kNN** | 「上次这个模具 + 这个料出这个缺陷，怎么调的」 | ⬜ **空白**（`_retrieve_similar_cases` 空函数已存在，见 §5.2） |

### 族 2 · 物理 / 机理与解析模型（注塑界最经典）

| 算法 | 工业界形态 | 本项目状态 |
|---|---|---|
| 充填时间 / 塑化时间 / 剪切速率上限 | 注塑工艺手册的基本计算 | ✅ **20/20 已物理化** |
| Scrapo 保压规则 | 保压压力 ↔ 浇口 / 制品重量换算 | ✅ 在 20 个算法内 |
| 成型窗口 Process Window / CLD 曲线 | 注塑工程师最认的工艺窗口图 | ⬜ 未成图（数据齐了，缺呈现） |
| 收缩率模型 → 尺寸预估 | 尺寸合格判定 | ⬜ 无尺寸字段 |
| CAE 仿真（Moldflow / Moldex） | 工业界「金标准」 | ⬜ 空白（物理设计文档里列为「阶段三（长期）」） |

### 族 3 · 仿真优化 SBO（拿 CAE 当评估器）

| 算法 | 工业界形态 | 本项目状态 |
|---|---|---|
| DOE（正交 / Taguchi / 响应面 RSM） | 参数范围探索 | ⬜ 空白 |
| 单目标：模拟退火 / GA / SPSA / Nelder-Mead | 全局寻优 | ⬜ 空白 |
| 多目标：NSGA-II / MOPSO / SPEAR | Pareto 前沿 | ⬜ 空白 |
| 代理模型加速：Kriging / RBF / XGBoost / 神经网络 | 降低仿真次数 | ⬜ 空白 |

### 族 4 · 数据驱动预测

| 算法 | 工业界形态 | 本项目状态 |
|---|---|---|
| 回归（岭 / SVR / RF / XGBoost / MLP） | 预测尺寸偏差、重量、翘曲 | ⛔ **0 标签，做不了** |
| 分类 | 缺陷有无 / 严重度 | ⛔ 同上 |
| 序列模型 | 直接预测下一轮参数 | ⛔ 迭代序列仅 10 条 |

### 族 5 · 优化闭环（数据少时的工业最优解）

| 算法 | 工业界形态 | 本项目状态 |
|---|---|---|
| **贝叶斯优化 BO**（GP 代理 + 采集函数） | 试模次数极贵时的首选 | ⬜ 空白 |
| 约束 BO / 多目标 BO | 带设备 / 材料硬约束的寻优 | ⬜ 空白 |
| **主动学习** | 专门挑「下一组最有信息量的实验」 | ⬜ 空白 |
| 强化学习 | —— | ❌ 工业界很少用（真实产线探索代价不可接受） |

### 族 6 · 混合（工业界主流形态）

| 组合 | 工业界形态 | 本项目状态 |
|---|---|---|
| 规则给初值 + BO / 代理模型微调 | 主流 | ⬜ 待建 |
| 代理模型 + 多目标优化 | 汽车 / 医疗 Tier-1 | ⬜ 待建 |
| 规则库 + 案例检索 + 少量实验校正 | **通用注塑 Tier-2/3 的主力形态** | ⬜ 差最后一块（案例检索） |

## 3. 选型筛子：按数据量级分层

> 工业界算法选型的硬约束不是「哪个更先进」，而是**「手上的数据量配不配得上它的前提」**。

| 族 | 数据前提 | 本项目是否满足 | 结论 |
|---|---|---|---|
| 族 1 · 知识 / 规则 | 无（规则是人写的） | ✅ | **已在做，且已是主力** |
| 族 2 · 物理 / 解析 | 几何 + 材料物性 | ✅ | **已完成（20/20）** |
| 族 1 · **浅 CBR** | 只要有「输入 + 动作」历史 | ✅ 45 条足够 | ⬜ **可做**（不依赖标签） |
| 族 5 · 主动学习 / BO | 只要能「试 + 评」 | ⚠️ 需先有可评估的 outcome | ⏳ **等标签** |
| 族 1 · **深 CBR**（含 Revise / Retain） | 需要 outcome 判「复用是否成功」 | ⛔ 0 标签 | ⏳ **等标签**（用户已在推进） |
| 族 4 · 回归 / 分类 | 需要成百上千条带标签样本 | ⛔ | ⏳ 等数据积累 |
| 族 3 · 代理模型 + 多目标优化 | 需要几百条闭环样本 + 目标函数 | ⛔ | ⏳ 中期 |
| 族 3 · CAE + SBO | 需要 CAE 授权 + 模具建模 + 仿真时间 | ❌ | **现阶段不划算**（见 §7） |
| 族 4 · 端到端深度学习 | 万级样本 | ❌ | **不做** |
| 族 5 · 强化学习 | 可承受大量试错 | ❌ | **不做** |

| | 浅 CBR | 深 CBR |
|---|---|---|
| 做什么 | 检索相似历史 → **参考它当时怎么调的方向** | 检索 → 复用其解 → **验证是否成功** → 沉淀 |
| 需要 outcome 标签？ | **不需要** | **需要**（判「复用是否成功 / 要不要 Retain」） |

该判断针对的是**深 CBR**，**至今成立**。
⇒ 本次不是推翻它，而是**补上被省略的那一半**：浅 CBR 现在就能做，深 CBR 等标签。

## 5. 真正的缺口：工业界「优化」的三要件

严格说，当前 fuzzy 是**「知识 → 参数」的单轮映射**，还不是「优化」。
工业界的优化需要三个要件：

| 要件 | 含义 | 本项目现状 | 缺什么 |
|---|---|---|---|
| **① 目标 / 质量标签** | 「这次调完到底好不好」 | `result` 45/45 全 `pending`；模型里无尺寸 / 重量 / 翘曲字段 | **试模结果回填流程** + 客观质量量（若有） |
| **② 优化器** | 目标函数 + 约束 + 搜索策略 | 无目标函数、无 Pareto、无「下一轮试什么」 | 目标定义、约束建模、BO / 多目标优化 |
| **③ 迭代闭环** | 多轮「调 → 试 → 评 → 再调」 | `previous_parameter` 仅 10/45 | 闭环流程跑起来 + 序列数据积累 |

### 5.1 注塑的核心矛盾是**多目标**

质量（尺寸 / 重量 / 翘曲）、周期、能耗、成本**互相冲突**。
当前形态「给一个值 + 置信度」= **隐含地替工艺员做了权重选择**。
工业界最终都要走到 Pareto 前沿（族 3 / 多目标 BO）。

> 这**不一定是缺点** —— 工艺员往往就想要一个能直接上手试的值。
> 但它决定了系统的定位：**现在是「参数推荐」，不是「参数优化」**。
> 要往「优化」走，第一步是**定义目标**（缺陷消除优先 → 尺寸 → 周期 / 能耗）。

### 5.2 已存在的扩展点（不是从零开始）

| 位置 | 内容 |
|---|---|
| `process/algorithms/llm/llm_algorithm.py:70` | `_retrieve_similar_cases(context)` —— **空函数**（`return []`），注释「向量检索相似历史案例」 |
| 同上 `:36` | `recommend()` 的 context 契约里**已经列了** `'tuning_history': [...]` 与 `'similar_cases': [...]` |
| 同上 `:54` | `is_available()` 恒 `False` ⇒ 引擎被 chain 自动跳过（占位状态） |
| `_refs/system/ai/process-ai-architecture-design.md:1030` | 「设计 RAG 相似案例检索 ☐ 未启动」 |
| `process/models/recommendation.py:37-39` | `source_type` 已预留 `rule_miner` / `doe` / `genetic` 取值 |

## 6. 演进路线（三阶段）

> 每阶段的「前置」是**硬门槛** —— 前置不满足就往下推，等于造一个无法验证的东西。

### 阶段 0 · 补标签与流程（**最高优先级，零算法成本**）

| 项 | 内容 |
|---|---|
| 目标 | 让 `TuningRecord.result` 从全 `pending` 变成**有值**；让 `previous_parameter` 序列变长 |
| 前置 | 无（这是**前置本身**） |
| 落地位置 | 业务侧「试模结果回填」流程；`result` + `result_detail`（字段已存在、取值域已定义） |
| 验收 | 标签覆盖率（建议先追 45 条存量回填，再看新增记录的新增量）；序列条数 |
| 风险 | 人工标注主观 ⇒ 标签噪声；建议配套「至少 N 条同口径样本才启用 ML」的门槛 |
| 备注 | **用户已在推进（"我也会上反馈标签的"）⇒ 这一阶段与用户并行** |

### 阶段 1 · 不依赖标签的补强（标签就绪前也能做）

| 项 | 内容 |
|---|---|
| 1a **浅 CBR** | 检索相似历史 → 参考其调整方向，作为**与 fuzzy 并列的第二推荐来源**（权重可配、可关闭）；落点：复用 `_retrieve_similar_cases` |
| 1b **成型窗口图** | 用已有的论域 + 设备上限画「工艺窗口」图（剪切速率 / 温度 / 粘度的可行区）—— **数据齐了，只差呈现**，工艺员一眼能懂 |
| 1c **解析模型做初值与可行性裁剪** | 把 20 个物理算法当作「基准初值」，fuzzy 给的是**偏离量**而非绝对值 |
| 前置 | 阶段 0 **不阻塞**（1a/1b/1c 都不依赖标签） |
| 验收 | 浅 CBR：**留一法**自评（拿历史记录当查询，看召回的邻居是否真的同缺陷同材料）；1b/1c：与现有 expert 输出对拍不劣化 |
| 风险 | 浅 CBR 会把「历史上调错了的动作」也召回 ⇒ 必须配合 `result` 过滤（**依赖阶段 0**）⇒ 过渡期可先只做**展示**（给工艺员看历史），不直接进推荐 |

### 阶段 2 · 有标签后的优化闭环

| 项 | 内容 |
|---|---|
| 2a **目标函数落地** | 把「缺陷严重度 / 尺寸偏差 / 周期」定义成可计算的目标；用代理模型（XGBoost / Kriging）拟合 |
| 2b **多目标优化** | NSGA-II 或多目标 BO ⇒ 出 Pareto 前沿（质量 vs 周期 vs 能耗） |
| 2c **主动学习 / BO 选下一轮试模点** | 「推荐下一轮试哪几个组合、预期消除哪个缺陷」—— 试模次数是稀缺资源，BO 的价值就在这里 |
| 2d **深 CBR / 规则挖掘** | 标签有了之后：`RuleMinerEngine` 从「缺陷 → 调整 → 结果」三元组挖高频模式，反哺规则库 |
| 前置 | 阶段 0 完成 + 闭环样本到**几百条**量级 |
| 验收 | 与 expert / fuzzy 三方对拍；人工评审 Pareto 解的可信度 |

## 7. 明确暂不做（及理由）

| 不做 | 理由 |
|---|---|
| ❌ CAE + SBO（Moldflow） | 授权 + 模具建模 + 小时级仿真 + 仿真与实际有偏差；**多腔复杂件且单件价值足够高**时才划算。物理设计文档已把它列为「阶段三（长期）」⇒ 维持 |
| ❌ 端到端深度学习 | 45 条 + 0 标签，样本量差 2~3 个数量级 |
| ❌ 强化学习 | 真实产线当 RL 环境，探索代价不可接受；工业界用 BO 替代 |
| ❌ LLM 直接给数值 | 数值可信度不如规则；建议 LLM 只做**知识问答 + 建议解释**（`llm_algorithm.py` 的 RAG 路线） |
| ❌ 现在扩 `doe` / `ga` / `neural` 引擎 | `AlgorithmRegistry` 已预留位置，但**前提未满足**；先补阶段 0/1 |

## 8. 待决策项（等用户把流程理清后再定）

1. **反馈标签的口径**：手工四档（`improved` / `worse` / `unchanged` / `qualified`）够不够？
   还是要引入客观量（尺寸 / 重量 / 翘曲）？
2. **标签粒度**：一次试模 1 条 `TuningRecord` 还是多轮？`previous_parameter` 序列怎么连续起来？
3. **案例检索的落点形态**：
   - 挂到 LLM 引擎的 RAG（`_retrieve_similar_cases` 现状）？
   - 还是独立成一个 `case_retrieval` 引擎，与 fuzzy / expert 并列进 chain？
   - 还是只在 UI 上做「历史相似案例」展示（最轻）？
4. **调优结果与「目标」的关系**：多目标（质量 / 周期 / 能耗）里，当前轮先优化哪个？
5. **是否需要「工艺移植」场景**（换料 / 换模 ⇒ 参数重推）—— 若要，则 CBR 的相似度定义要变（跨材料族）。
