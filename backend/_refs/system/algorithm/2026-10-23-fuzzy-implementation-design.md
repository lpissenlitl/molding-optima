## §0 范围与边界

### 0.1 实现对象

> 把「缺陷反馈 + 当前工艺参数」翻译成「每个参数该调多少、什么方向、凭什么」。

**输入契约**

| 类别 | 内容 | 性质 |
|---|---|---|
| 缺陷 | 名称 + 严重程度 + 位置 | 离散 |
| 工艺参数快照 | 约 27 个参数真实值 | 连续 |
| 上下文 | 材料、模具/产品、设备、规则库 | 静态参照 |

**输出契约（多视图）**

引擎一次计算，输出**多种表达**，由前端 / 业务层选择呈现方式——**不在引擎里做二选一**。

```
Recommendation (per param)
├─ value / direction   主建议：加权平均后的建议值与方向
├─ dominant_rule       argmax 命中的那条规则（「单条工艺知识」视图）
├─ contributors        全部命中规则 + 各自权重（完整信息视图）
├─ confidence          聚合置信度
├─ conflict            冲突标记（方向不一致 / 目标档位不一致）
└─ excluded            被抑制或不可用的规则 + 原因
```

✅ **2026-10-23 拍板**：择优（argmax）与加权平均**不是二选一的引擎分支**，而是同一份计算的两种输出视图。前端可只显示 `value`、也可显示 `dominant_rule`、也可展开 `contributors`。

### 0.2 明确不做

- 不做参数寻优（不搜索最优解）
- 不预测缺陷是否消除
- 不做跨参数约束求解
- 不做规则自动归纳

## §1 三种语义必须分离【已定】

一段规则 `IF SHORTSHOT_low AND IV0_high THEN IV0_reduce_3.8` 压了三种性质不同的东西：

| 成分 | 性质 | 归属层 | 实现方式 |
|---|---|---|---|
| 缺陷名 + 缺陷档位 | 离散开关 | 路由层 | 精确匹配，选出适用规则集 |
| 参数名 + 档位词 | 连续门控 | 门控层 | 隶属度 μ ∈ [0,1] |
| 结论（减 3.8） | 绝对量 | 聚合层 | 确定性合成，不被强度缩放 |

**为什么这是根因**：混在一起会导致两个后果——缺陷被当连续量算（恒真）、结论被相对强度缩放（工艺知识被稀释）。任何实现方案先拆开这三者，后面才有意义。

## §2 分层：五层，每层单入口

```
契约层  Contract    形状与含义（数据 + 校验）
语义层  Semantics   词表：参数名 / 档位词 / 动作词 / 维度类型（纯数据，无逻辑）
构建层  Build       规则 + 元数据 → 可执行推理计划（纯函数）
推理层  Infer       计划 + 当前值 → 结论（纯数值）
编排层  Orchestrate 取数、组装、跨引擎合并、落库
```

**每层硬规则**（每条对应一类已犯过的错）

| 层 | 必须 | 禁止 |
|---|---|---|
| 推理层 | 无 I/O、无日志、无全局可变状态、无随机；失败显式抛出 | 跳过前件、猜值、容错降级 |
| 构建层 | 纯函数，输入相同输出必相同 | 依赖执行顺序的隐式布局 |
| 语义层 | 只被构建层消费 | 词表变更波及推理层 |
| 编排层 | 唯一允许碰 DB 的地方 | — |

## §3 语义层

### 3.1 维度类型【主张】

不是所有参数都是连续量。

| 类型 | 例子 | 门控算子 | 输出 |
|---|---|---|---|
| 连续 | 注射速度 / 压力 / 温度 / 时间 / 转速 | 高斯隶属度 | μ ∈ [0,1] |
| 布尔 | 保压启用、成型段启用 | 严格相等 | 0 / 1 |
| 枚举 | 模态（保压段 / 成型段 …） | 集合成员 | 0 / 1 |
| 比例 | 余量类 | 相对基准的隶属度 | μ |

不引入此概念，布尔型与枚举型参数只能被硬塞进高斯，得出无意义的 μ。

### 3.2 档位词 → 桶的语义【方向已拍板 · 映射算法已实现 · ⚠️ 未接线】

**数据事实**：字段档位数**由元数据决定**（旧版固定 3 档；现库 5 档为主）；规则只出现 low / medium / high。

✅ **2026-10-23 拍板的两条原则**：

1. **档位数是元数据属性，不是算法假设**。算法不得假定“5 档”或“3 档”——**同一套规则在任意档位数下都应能推理**
2. **档位词 = 论域上的相对位置**（分位语义），不是绝对阈值

**映射算法（序数自适应）【主张】**

```
设字段档位数 L、该参数实际使用的语义词数 n（按低→高排序）
if n == L:  桶_i = i                                    # 词与桶一一对齐
else:       a = 1, b = L-2                              # 两端桶留给极端词
            桶_i = round( a + i*(b-a)/(n-1) )
```

| L | n | 映射 | 备注 |
|---|---|---|---|
| 3 | 3 | low→0, medium→1, high→2 | **与旧版完全一致** |
| 5 | 3 | low→1, medium→2, high→3 | E2 语义（两端桶留给 extreme 词） |
| 5 | 2 | low→1, high→3 | |
| 4 | 2 | low→1, high→2 | |

**关键性质**：
- **3 档时行为与旧版一致** ⇒ 不需要改存量规则
- **5 档时自动切到 E2 语义** ⇒ 保留 5 档 + 不改规则 = 两者可兼得
- 语义词数 n **从规则库实际用词统计得出**，不预设

⚠️ **风险**：**档位数变化 = 规则行为变化**（同一个 x，桶位不同 ⇒ 判定不同）。
⇒ 建议：① 尽量统一前件参数的档位数；② 编译产物记录“编译时所用档位数”，便于诊断；③ 档位数变更需走与规则变更同级的审计。

## §4 构建层：规则 → 推理计划

### 4.1 为什么要有编译这一步

规则文本是**人写的、面向人的**；推理需要**机器可执行的、数值化的**。中间这层编译，让差异**显式暴露在编译期**，而不是散落在推理时临时解析、临时跳过。

### 4.2 编译产物 = 推理计划（Plan）【主张】

```
RulePlan
├─ rule_id / defect_code / defect_level
├─ scope:  {规则库, 层级, priority, 材料, 产品}   # 适用范围
├─ gates:  [Gate(param, level_word, domain(min,max), sigma, kind)]
├─ conclusion: Conclusion(action, param, amount, amount_kind, text?)
└─ diagnostics: [...]   # 编译期发现的问题
```

**编译期就要暴露问题**：引用不存在的参数、词表外档位词、结论缺调整量、论域缺失——记为该规则诊断，并让规则**显式不可用**，而不是推理时静默跳过。

### 4.3 列布局 vs 显式结构【主张】

保留「一次性编译成执行计划」的思想（旧版最有价值的架构资产），但用显式结构替代裸矩阵：

- 每个 Gate 自带自己的论域与 σ，不依赖全局列区间
- 桶索引由语义层函数计算并**校验**；越界是编译错误，不是运行期静默写错列
- 规模上 1643 条规则 × 平均 2 门控 ≈ 3~5k 个 Gate，不需要 numpy 矩阵
- 附带收益：可解释性——能直接说清「用了哪些门控、各自 μ 多少」

### 4.4 结论形态是一等公民【主张 · 2026-10-23 第 2 轮】

**问题**：旧版把「规则的结论形态」当成了「引擎的实现分支」——模糊等级结论被迫走 Mamdani 类、数值结论被迫走零阶 T-S 类。规则数据形态一变，引擎行为整套换掉。

**主张**：引擎只保留**一条**推理路径（前段共享），结论形态由 `RulePlan.conclusion.kind` 承载，聚合层按 kind 分派。

```
kind=amount   数值调整量   → 加权平均
kind=level    模糊档位     → 先合成模糊集，再反模糊化（需该参数的「调整量论域」）
kind=ratio    百分比       → 加权平均（作用在比例上）
kind=text     检查/提示    → 不进数值聚合，直接作为检查项输出
```

**数学上的统一**（两种形态自动涵盖，无需两套代码）：

```
y = defuzz( Σ_i w_i · μ_i(z) )
     常数结论  ⇒ 退化成一个单点分布 ⇒ defuzz 退化为加权平均
     模糊集结论 ⇒ 标准 Mamdani
```

**前置条件**：level 形态需要为每个可调参数标定「调整量论域」（旧版的 `action_max_val` / step）。
⚠️ 该元数据现状为空转（只服务过空跑路径）——详见附录 A.5。
✅ **2026-10-23 已拍板**：**保留 level 形态**；调整量论域按「默认值 + 实际值修正」方式提供（随设备、材料等信息更新）——见 §7.2。

### 4.5 规则可更新性对设计的要求【主张 · 2026-10-23 第 3 轮】

前提：规则库**不是静态知识**，会经由数据更新（人工录入 / 数据归纳两种来源）。

| # | 要求 | 理由 |
|---|---|---|
| 1 | **编译产物带版本戳**（Plan = Compile(rules, metadata)，缓存键含规则与元数据版本） | 构建层是纯函数 ⇒ 编译廉价可重复；规则变则缓存失效 |
| 2 | **规则携带来源标记**（专家 / 数据归纳 / 系统默认）+ 各自置信度 | 两种来源权威性不同；priority 不能只是数字 |
| 3 | **scope 完备性列为编译期诊断项** | 数值结论是绝对经验值，脱离材料 / 产品 / 机台即失真 |
| 4 | **数值结论的修改留痕**（谁、何时、为何 3.8→5.0） | 规则可更新 ⇒ 来源可追溯是信任基础 |
| 5 | **amount 形态是数据归纳的天然产物**，level 形态偏专家表达 | 支撑「amount 为主 + level 保留」双轨设计 |

⚠️ **需复核的历史判断**：旧版 `fuzzykit/induction/`（4778 行，含 ripper / irep / catnap / discretize 等规则归纳算法）此前被判定为「新版不需要、不迁移」。若「规则从数据更新」进入中期计划，该判断需**单独复核**——不是现在迁移，而是评估是否值得复活。

## §5 推理层：纯数值

### 5.1 模糊化

- 高斯隶属度：μ(x) = exp(−(x−c)² / 2σ²)
- 中心 c = 档位在**标定后论域**上的目标位置
- ⚠️ **易错点**：对称相邻桶的高斯交叉点**恒在两中心中点**，与 σ 无关
  ⇒ σ **不改变档位分界**，只改变**过渡带宽度**
  - σ 大 ⇒ 宽松（刚偏离中位就算"偏高"）
  - σ 小 ⇒ 严格（要很接近峰位才算）
- 【主张】σ 是**可标定数据**（随词表或随参数配置），不是代码常量

### 5.2 多前件连接【主张】

用 **min（弱连接）**：规则是 AND 条件判断，最弱证据决定这条规则能不能用。

- `prod` 会让多前件规则被指数级稀释
- min 的性质：≥2 门控时真正起作用；单门控时 min = 该值本身，天然正确

### 5.3 门控状态机：未命中 / 边界态 / 明确态【已拍板 · 2026-10-23 第 5 轮】

高斯隶属度对任意有限 x 都 > 0 ⇒ **"命中"不等于"条件满足"**。

**两级判据**（τ 与 ε 分工明确）

```
对参数 p 的所有可用语义词算 μ，取 μ_max、μ_second
competition = μ_max − μ_second

① μ_max < τ                      → 未命中：门控不生效
                                    （τ = 命中门限，按参数类型可配）
② μ_max ≥ τ 且 competition < ε    → 边界态：生效但降权
                                    （ε = 竞争容差，可配）
③ competition ≥ ε                 → 明确态：正常生效
```

**边界态的处理**（✅ 2026-10-23 拍板：选项② —— 生效但降权）

```
β_p = clamp(competition / ε, β_min, 1)      # 连续衰减，无阶跃
weight_i = μ_i × priority_i × β_p            # β_p 是参数级因子
```

- **连续衰减**而非固定折扣：竞争越接近 0 权重压得越低，接近 ε 时恢复为 1
- 该参数的建议标记 `boundary = true` 并携带 `competition`，供前端提示“把握不大”
- `dominant_rule` 照常输出（argmax 仍可选出主导规则）

**三态的实际含义**

> ⚠️ **更正此前表述**：选项②**就是**三态判定，只是“边界态”选择**降权**而非丢弃。
>
> | 状态 | 含义 |
> |---|---|
> | ① 未命中 | 这个条件根本没成立 |
> | ② 边界态 | 勉强成立，但处在两档之间，把握不大 |
> | ③ 明确态 | 条件明确成立 |

**为何不选“不给建议”（丢弃）**：规则库中 medium 仅用 492 次，许多参数可能只用 low/high ⇒ 在论域中位处两者隶属度恒等 ⇒ 丢弃会导致**大面积不给建议**。降权方案保留产出，同时把不确定性反映在权重上。

### 5.4 聚合层【主张】

对**每个输出参数**分别做：

```
weight_i = μ_i × priority_i × β_p
建议量 = Σ(weight_i × 结论量_i) / Σ(weight_i)
```

三条原则：

1. **按输出参数分组**——不跨参数共享分母
2. **用加权平均，不是加权和**——结论是绝对工艺知识，μ 只决定"该听谁的"
3. **priority 进权重**——规则权威度体现为权重倾斜，权重和恒为 1
4. **β_p 边界态衰减**——参数级因子，对该参数上所有规则统一生效（§5.3）

✅ **2026-10-23 调整**：本层只负责算出**加权平均**这一路结果；argmax 那一路（`dominant_rule`）由同一批命中规则**并行产出**，作为输出视图之一（§0.1），**不做二选一**。

### 5.5 冲突必须显式化【主张】

同参数命中规则给出相反方向时，加权平均会让 +3.8 与 −3.8 抵消成 0 —— **最危险的静默失败**：输出里有建议、实际什么也不会改。

【主张】输出契约区分「一致 / 冲突」：一致 → 给建议值；冲突 → 给主导方向 + 列出分歧依据。

✅ **2026-10-23 调整**：冲突信息作为输出视图 `conflict` 存在，**不阻断**主建议 `value` 的产出；前端选择是否呈现。

### 5.6 数值结论与提示结论分流

- 数值结论（加/减 X、减 Y%）→ 进聚合
- 检查类结论（"请检查锁模力是否不合理"）→ 不参与数值聚合，直接作为检查项输出

## §6 缺陷的定位【主张】

**缺陷只做路由，不做门控。**

理由：缺陷程度已通过"选哪一套方案"表达；若还要让严重度影响权重，等于同一档位内再分一次严重度——但数据侧只有 low/medium/high，且已被路由吃掉。

保留扩展位：若将来要连续化缺陷强度，元数据层已有现成落点（缺陷类关键词，论域 0~1，正好承载严重度 0~1）。

## §7 论域：实现的隐含前提

门控的 μ **完全由论域决定** ⇒ 论域是数据，不是代码常量。

### 7.1 两种候选基准的关键区分【核实 · 2026-10-23 第 6 轮】

⚠️ **“设备量程” 与 “实际运行区间” 是两回事，不能混用同一个字段。**

| | 来源 | 现状 | 能解决 | 不能解决 |
|---|---|---|---|---|
| **(a) 设备量程** | 机台档案 `max_set_*` / `max_*` | ✅ **数据已在库**（schema 必填、`specs.py` 已定义契约），但**未接入论域** | 跨机台一致性（100 MPa 机与 350 MPa 机不应同档） | “真实值只占论域 18%~32%”（设备量程本身比工艺窗口宽得多） |
| **(b) 实际运行区间** | 历史工艺参数统计（分产品 × 材料） | ⚠️ 需样本（现有 49 条） | 档位分位的落点（分位语义的前提） | 跨机台一致性 |

**关键事实（2026-10-23 核实）**：`max_set_*` / `max_*` 这套设备数据目前**只用于「工艺移植换算」**（`process_transplant.py` / `AlgorithmsTransplantView`），**没有进模糊推理的论域**——引擎判“低/高”用的是 `RuleKeyword.range_min/max`（静态、种子默认值、全库一套）。

旧版走查原话：**“设备上限没进论域 → 100 MPa 的机与 350 MPa 的机判成同一档。”**

⚠️ **补充核实（2026-10-23 第 7 轮）**：**旧版其实实现过这个机制**（`read_machine_setting_para`），但**只换上界**，且只覆盖 14 组参数——**现行 `molding-optima` 是迁移时丢失了**。完整链路与三个限制见**附录 B**。

⇒ **性质变了**：论域标定**不是“新建能力”，而是“已有数据没接线”**（继 `resolve_bucket` 之后的第二例“写好不接线”），接入成本远低于原先估计。

**主张：两者分层，不共用字段**

```
档位分位 ← (b) 实际运行区间（分产品 × 材料）   ← 决定 μ 的中心与 σ
越界检查 ← (a) 设备量程                      ← 超出则标记 out_of_domain + 降权（§5.4）
```

⚠️ **2026-10-23 第 8 轮 · 实测体检后的修正**（完整数据见**附录 C**）：

| 实测结论 | 对主张的影响 |
|---|---|
| 静态论域 vs 设备量程：**42/46 不一致** | 支持 (a) 需要接线 |
| 接线后判级会变：**12/46（26%）**，且 IP0-IP3 **全部** L2→L3/L4 | ⬆️ **“恢复旧机制”收益比第一版估计大**——现版论域偏大 ⇒ 真实值**系统性被判偏低档** |
| 分位落点不合理：**8 个参数**（★ PT0/PT1 论域**偏小 450%+** ⇒ 恒定高档；IL0/IL1 偏小 189%；BT/NT 越界 5×，IP0/IV0-2 只占 0%） | ⬆️ **真正的问题在 (b)**，且 **(a) 一个都解决不了**（IP0 的设备上限 100 比现版 200 更小，真实值 84 仍占 0%） |
| 无设备基准的参数类：**137/183** | ⬆️ 全部是温度/时间/模式枚举类 ⇒ (a) 本来就不该覆盖它们 |
| ★ **同一物理量论域自相矛盾：7 组** | ⚠️ **降级为“待确认”**：`BT` 实测对应 `brl_temp_stg` 恒为 5 ⇒ 很可能不是同一物理量，**不能仅凭论域不同判 bug** |

⇒ **优先级重排**：先修 §7.4 的元数据矛盾（成本最低、危害最大），再接 (a)（跨机台一致性），(b) 独立推进。

### 7.2 基准来源分治【主张 · 2026-10-23 第 8 轮 · 已由体检数据支撑】

| 参数类型 | 覆盖量 | 基准 |
|---|---|---|
| 设备直采类（压力/速度/转速/行程/位置） | 46 个 | 上界 (a) 设备量程；分位参照 (b) 实际运行区间 |
| **档位型（取值离散，实测 86% 的参数）** | **46/53 个参数** | **实验取值集合的中点边界**（§7.5.2 方式 C）|
| 温度类 | BT / CT / NT / MT / IDT / HRT 等 | 材料加工窗口（(a) 不成立，也**不应**成立） |
| 时间类 | PT / SCT | 工艺节拍约束 |
| 模式/枚举类 | DMAM / DMBM / VPTM | **不需要连续论域**（离散档位） |
| 余量/比例类 | DVAM / DVBM / ET / DDAM / CLAMP | (b) 产品 × 材料历史分位数 |
| 缺陷类 | 128 个 | **不参与物理论域**（缺陷等级是离散档位） |

**兜底**：历史分位数。样本量少，只能代表当前产品/材料，但比“设备物理极限当论域”好一个数量级。

【主张】论域标定可与实现并行推进，两者**乘法相关**。

### 7.3 输出侧论域（level 形态专用）

**用途**：level 形态的结论表达在「调整量论域」上（该参数能被调整的范围），再由反模糊化得到具体数值。

**元数据形态**【已拍板 · 2026-10-23】：

| 项 | 规则 |
|---|---|
| 默认值 | 随参数类型给一套默认值，**仅用于测试运行** |
| 实际值 | 随设备、材料等信息更新 |
| 维护方式 | 与输入侧论域同样归入元数据层，可随数据更新 |

**要点**：

- 与输入侧论域**同源不同向**：输入侧 = 工艺参数的取值范围（判“低/高”）；输出侧 = 调整量的取值范围（表达“调到第几档”）
- 二者**不共用字段**（避免旧版 `action_max_val` 那种“只服务空跑路径”的悬空设计）
- 元数据缺失时：level 形态规则**显式不可用 + 原因**，不静默跳过（§8）

### 7.4 元数据论域的上下界填错（体检新发现）【2026-10-23 第 8/9 轮 · 核心】

⚠️ **有一类问题既不是 (a) 也不是 (b)：论域元数据本身就填错了。**

体检发现 **7 组**“总称关键词”与“分段关键词”论域不一致（附录 C.5）。⚠️ **但根本问题不止“组间不一致”——是单个参数的上下界填错**。

**端到端体检（附录 D）实测：全库 1643 条启用规则中，约 669 条规则的 IF 门控 + 643 条 THEN 结论受影响。**

| 参数 | 论域 | 引擎实测真实值 | 越界率 | 恒定判定 | IF 引用 | THEN 引用 |
|---|---|---|---|---|---|---|
| **MBP0** 计量背压 | `[10, 50]` | 3.4~5 | **100%** | **恒 L0（恒低档）** | **179** | 179 |
| **BT** 料筒温度 | `[0, 50]` | 230~250 | **100%** | **恒 L4（恒高档）** | **167** | 167 |
| **PT0** 保压时间 | `[0, 10]` | 15~60 | **94%** | **恒 L4** | **147** | 147 |
| VPTL VP切换位置 | `[30, 60]` | 22.8~30.5 | 88% | 偏 L0 | 82 | 73 |
| MEL 计量终点位置 | `[0, 200]` | 190~491 | 81% | 偏 L4 | 63 | 36 |
| **NT** 喷嘴温度 | `[0, 50]` | 230~255 | **100%** | **恒 L4** | 31 | 31 |
| IL0 注射位置 | `[0, 150]` | 181~464 | 96% | 恒 L4 | **0** | 0 |

⇒ **“恒 L0 / 恒 L4” = 该参数的某个档位条件恒真、另一个恒假** ⇒
例如 `BT_low` 永远不命中、`BT_high` 永远命中；`MBP0_high` 永远不命中。

⚠️ **对“论域过宽”的直觉修正**：不是“过宽 ⇒ 迟钝”，而是 **“上界偏小 ⇒ 恒高档；下界偏大 ⇒ 恒低档”**——
真实值整体被钳在论域外侧，某一档条件恒真、另一档恒假 ⇒ **判档区分度归零**。
（第 11 轮口径校准：这是“判得不准”，不是“不能用”。）

⚠️ **另两类错位（比论域更根本）**：

| 类型 | 实例 | 后果 |
|---|---|---|
| **字段语义错位** | `CT` 引擎取 `cool_t`（**冷却时间**，真实 5~9.5 秒），但 `CT` 的别名是“**模具温度**”、论域 `[0,120]` | 规则 `CT_add_2` 意为“模具温度+2”，实际是“冷却时间+2 秒”并写回 `cool_t` ⇒ **182 次引用全部语义错** |
| **取值缺失** | `BT1` 反查业务字段也是 `brl_temp_1`，但归一化时 `brl_temp_1` → `BT`（段1→家族名）⇒ **`BT1` 取不到值** | `BT1_low` 的 2 条规则**永远不命中**（静默） |

⇒ **优先级重排**：这类问题**成本最低（改数据/改映射）、危害最大** ⇒ **排在 (a)/(b) 之前**。

### 7.5 论域必须来自实验数据【2026-10-23 第 10/11 轮 · 核心】

⚠️ **先纠正一处定性过度（第 10 轮的表述）**

第 10 轮我把现象说成“门控**彻底失效**”“**空转**”“**结构错配**”——**表述过重**。
第 11 轮用户纠正：**“算法这里只存在数据越精准就越有效的问题，不是能用/不能用的问题。没你想的那么严重。”**

⇒ 正确表述：**论域不准 ⇒ 判档不准**，这是**精准度**问题，不是“能不能用”的二元问题。
⇒ 因此本节的结论**不是**“加准入规则 / 角色声明 / 门禁”，而是——**把论域数据做精准**。

#### 7.5.1 现版静态论域把判档压成了单档

实测（附录 E.6，22 个高频参数）：

| 指标 | 现版静态论域 |
|---|---|
| 平均最大档占比 | **98%** |
| 归一化熵 | **0.00 ~ 0.39**（0 = 完全没有区分度）|
| `BT` / `NT` / `CT` | 熵 = **0.00**（100% 落进同一档）|

⇒ 这不是“不能用”，是**判得不准**：真实值明明分散，论域却把它们全判成一档。

#### 7.5.2 怎么取界才准：三种方式实测对比

| 方式 | 边界来源 | 平均最大档占比 | 说明 |
|---|---|---|---|
| **A 现版** | `RuleKeyword.range`（静态种子值） | **98%** | 与实验数据脱节 |
| **B 贴 min/max** | `[实验最小, 实验最大]` | 81% | 众数仍独占一档（离散取值下无效）|
| **C 取值集合中点切** | 实验值去重排序，**相邻取值中点**为边界 | **74%** | 边界对齐真实档位 |

**方式 C 对 22/22 个参数都优于方式 A**；`BT` 熵 0.00→0.70、`NT` 0.00→0.77、`CT` 0.00→0.90、`BT2` 0.00→0.90。

⇒ **这就是“数据越精准越有效”的操作化**：论域边界取**实验取值集合的中点**，判档才能对齐真实档位。

⚠️ **残留限制（不是论域能解决的）**：`IV0` / `IP0` / `MP0` / `MSR0` 即使方式 C 仍是 94~96% 单档 —— 因为众数本身占 94%，**任何切法都压不下去**。⇒ 这属于“实验数据分布如此”，不是算法问题。

#### 7.5.3 落到本次重构：论域来源改为实验数据

这是旧版 `read_machine_setting_para`（第 7 轮核实）思路的自然升级：

| | 旧版 | 本次重构 |
|---|---|---|
| 覆盖参数 | 14 组 | 全部参数 |
| 替换内容 | 只换 `max_val` | 整个边界集合（取值中点）|
| 数据源 | 设备实际参数 | **实验数据（工艺参数记录）** |

**待定的三个细节**（§10-T）：

1. **档位数**：取值集合有 k 个 ⇒ k 个桶？还是映射到规则声明的档位数（第 4 轮「序数自适应档位映射」已有机制）？
2. **绑定键**：按 产品 / 材料 / 模具 / 机台 哪个维度分组？（当前 49 条实验数据全部来自 1 个「材料×模具×机台」组合）
3. **更新时机**：实验数据入库时重算，还是定时批量？

#### 7.5.4 量纲类型：连续量 vs 档位量（降级为实现细节）

实测 86% 的参数取值离散（≤6 个不同值）⇒ 边界取“取值中点”比“等距切”贴合。

⇒ **不需要额外引入“量纲类型”标签** —— 取中点这一条规则已经自动适配离散与连续取值。
⇒ 之前提的“准入规则 / 角色声明 / 可分档性门禁”**收回**：那些是在解决“能用/不能用”，而问题本是“判得准不准”。

⚠️ **一条留待观察**：`IV0_add_2` 这类结论，在档位型参数上加 2 可能落到非法的档位值（30→32）。⇒ 结论形态 `amount` vs `level` 的选择留待 §10-V。

## §8 契约与失败语义

- **context 契约**：`process_parameter` **只含工艺参数**；设备 / 材料 / 模具各自独立 key，不糅合
- **校验分两处**：入库时（规则 / 词表非法 → 拒绝入库，报明确原因）；编译时（引用未知参数 → 编译失败并列出原因）

**禁止静默降级**

| 失败情形 | 错误做法 | 正确做法 |
|---|---|---|
| 元数据取不到 | 猜一个论域继续算 | 显式失败，不产出建议 |
| 规则引用未知参数 | 静默跳过该规则 | 标记该规则不可用 + 原因，并在输出体现 |
| 规则无有效门控 | 当作正常无命中 | 显式标注"前提无法满足" |
| 推理无命中 | 返回空列表无解释 | 返回"无适用建议" + 已评估规则数 |

### 8.2 反馈闭环与规则抑制【主张 · 2026-10-23 第 4 轮 · 新增机制】

**业务事实**（用户提供）：工艺员按建议调完一模 → 下一模反馈"没用" → 若继续用同一调整逻辑就无效 → **需要切换别的调整逻辑**。

⇒ 这是**跨轮次闭环**。现有设计只有“输出建议”一环，**没有“执行 → 反馈 → 抑制上一轮规则”**——这是系统完备性的真实缺口，不只是算法问题。

**前提**：抑制必须能指向**具体规则**，因此输出必须携带 `rule_id`（`dominant_rule` / `contributors` 已具备）。

**数据模型**

```
AttemptRecord
├─ attempt_id / session_id / process_record_id   （哪一模）
├─ defect_code                                   （针对哪个缺陷）
├─ applied: [{rule_id, param, action, amount}]    （执行了什么）
├─ outcome: improved | no_effect | worse | unknown
└─ created_at
```

**抑制层级**（默认 L2）

| 层级 | 抑制对象 | 适用 |
|---|---|---|
| L1 规则级 | 同一条 `rule_id` | 这条规则本身没用 |
| **L2 参数-方向级**（默认） | 同参数 + 同动作方向 | “加过了没用，那就试试减” |
| L3 参数级 | 该参数的全部调整 | 该参数怎么调都不行 |

**时效与解除**（防死锁，不可省）

- 抑制默认在**下一轮**生效
- 解除条件（任一）：
  - 该缺陷已消失 → 全部解除
  - 关键参数发生显著变化（超容差）→ 工况变了，原抑制失效
  - 连续抑制轮次超上限 → 强制解除，允许重试
- **兜底**：无可用规则时显式输出“无可用建议（已排除 N 条上轮无效规则）”，**不得空输出**

**对各层的影响**

| 层 | 影响 |
|---|---|
| 契约层 | `context` 增加 `attempts`（近期尝试与反馈）——输入从“当前状态”扩展为“当前状态 + 近期历史” |
| 路由层 | 先抑制过滤，再做特异性匹配；输出携带“被排除的规则及原因” |
| 聚合层 | 抑制是**激活前**的规则级过滤，与聚合策略（激活后如何合并）**互不冲突** |
| 输出层 | `excluded` 字段：排除项 + 原因 |

⚠️ **规则内容变更时抑制是否仍成立**：建议绑定 `rule_id + 规则内容哈希`——规则被改过则抑制失效（那是另一条知识了）。

⚠️ **前端缺口**：现有前端只有「缺陷反馈」流程，**没有“建议执行结果”的反馈入口**——本机制需前端新增一项反馈。

## 附录 A · 旧版三种推理形态对照（2026-10-23 核实）

> 来源：`inovance-cooperation/HsMoldingService/mdprocess/utils/fuzzykit/fuzzy_core/models/nets.py`
> 与 `fuzzy_core/functional/defuzzy.py`。本附录用于给"继承/重设计"提供准确锚点。

旧版包里同时存在三条互不相同的推理路径：

| # | 路径 | 类 | 结论形式 | 聚合方式 | 生产状态 |
|---|---|---|---|---|---|
| 1 | **argmax 择优 + 重心反模糊** | `FuzzyRuleNet`（Mamdani） | 模糊等级（`X_add_low`） | **argmax 选一条** → 截断 → 重心法 | **空跑**（规则库无该形态结论） |
| 2 | **零阶 T-S** | `NumTskRuleNet` | 常数（`add_3.8`） | **按输出分组加权平均** | 生产主路径（1547 条） |
| 3 | 一阶 T-S | `TskRuleNet` | 线性函数 | 加权平均 | 死类占位 |

### A.1 路径 1（Mamdani）的真实行为

```
membership_degrees[列] = 每参数每桶的隶属度
rule_activations[i]    = np.min(该规则非零门控列)      ← min 连接
rule_to_outputs[idx+i] = np.max(命中该结论级别的激活度)
final_rule             = argmax(被标记规则的激活度)      ← 单条规则决定「动作方向」
若 Σ rule_to_outputs < 0.01001 → 该参数输出置 0        ← 无效激活 = 丢弃，不是降级
res[i] = defuzz(截断后的输出隶属度, 'centroid') × action
```

⚠️ **与"记忆中的旧逻辑"的三处偏差**：

1. **没有"切换次一级"**：规则无效时是**整参数置零**，不是 fallback 到次优规则
2. **方向来自单条** argmax 规则；数值来自反模糊化（不是该规则的常数结论）——是混合体
3. **"无效"由魔数 0.01001 定义**，无业务含义

### A.2 路径 2（零阶 T-S）的聚合方式

```
activations_sum = np.sum(rule_activations)   ← 全局分母，跨参数共享
sol_param[k]    = Σ(sol_matrix[.,k] × new_activations)
```

⚠️ 加权**和**（非平均）⇒ 结论被乘上相对强度；分母跨参数共享 ⇒ 跨参数摊薄。

### A.3 对本设计的影响

| 旧版资产 | 处置 |
|---|---|
| min 连接（`np.min(conditions)`） | **继承**（§5.2 主张一致） |
| 隶属度按参数/桶逐列计算 | **继承**，但论域与 σ 参数化、桶位校验 |
| argmax 择优 + 魔数阈值 | **重新设计**（§5.3 门限 + §5.4 分组加权平均） |
| 全局归一化 | **废弃**，改为按输出参数分组 |
| 重心反模糊（路径 1 专用） | 新版不需要（结论已是数值） |

### A.4 σ 的默认公式（此前未记录）

```
σ = (论域跨度) / (2 × (档位数 − 1))
例：论域 [0,120]、5 档 ⇒ σ = 15（与旧版实测一致）
```

⚠️ **更正**：这个公式**不是随手写的**——它恰好使相邻档位在两中心中点处隶属度相等（交叉高度 = exp(−0.5) ≈ 0.607），是一个**有意的合理默认**。

⚠️ **但存在一条此前未记录的传导路径**：

```
论域过宽（种子默认值 120，真实值只占 18%~32%）
      ↓
σ 随论域线性放大（15 vs 标定后的 ~3.75）
      ↓
门控整体迟钝（μ 普遍偏高、判定边界糊）
      ↓
档位判定跟着漂移
```

⇒ **标定论域一箭双雕**：既修「档位不可达」，也修「门控锐度」。之前只记录了第一条传导路径。

⇒ 设计结论：σ 默认沿用此公式，但**改为可标定数据**，不硬编码。

### A.5 结论形态与推理路径的硬绑定（旧版混乱的结构性根因）

| 想要表达的结论 | 被迫走的路径 | 连带代价 |
|---|---|---|
| 模糊等级（`X_add_low`） | `FuzzyRuleNet`（Mamdani） | 必须为每个输出参数配**输出论域**（`action_max_val` / step） |
| 数值量（`X_add_3.8`） | `NumTskRuleNet`（零阶 T-S） | 全局归一化加权和（结论被缩放、跨参数摊薄） |

**混乱的具体表现**

1. 推理链**前段被复制两遍**（模糊化 + min 连接 + 激活度），改一处漏一处
2. 结论形态 → 路径**无显式 dispatch**，靠字段有没有值隐式决定
3. `action_max_val` **只服务于一条空跑路径**（设计债）
4. `levelN` 同时承担「档位映射」与「输出变量第几个模糊集」两种语义
5. `HS_MAPPING_DICT` 混装动作 / 编号 / 语义三种语义
6. 魔数 `0.01001`、列布局隐式契约

**一句话诊断**：旧版把「规则的结论形态」当成了「引擎的实现细节」，而它其实是**业务数据的一部分**。

⇒ 设计原则（见 §4.4）：**结论形态是业务数据，不是代码分支。**

## 附录 B · 旧版论域链路（2026-10-23 核实）

> 来源：`HsMoldingService/mdprocess/services/rule_service.py`、`mdprocess/services/inovance_service.py`、
> `mdprocess/utils/fuzzykit/fuzzy_core/models/nets.py`

### B.1 完整数据流（实测）

```
RuleKeyword 表
  all_range_min / all_range_max / action_max_val / level
        ↓ rule_service.load_rule_from_database()  L327-333
keyword_array = [{'keyword', 'lvl', 'min_val', 'max_val', 'step'}]
        ↓ inovance_service.read_machine_setting_para(machine_info, keyword_array)
   max_val ← 设备 max_set_* / max_injection_stroke      ← 只改上界
   min_val ← 不动（保持表内默认值）
        ↓ nets.py  L275
FuzzyFeature(k, [k_dict['min_val'], k_dict['max_val']], f_level=k_dict['lvl'])
        ↓
σ = (max_val − min_val) / (2 × (lvl − 1))          ← 随论域线性缩放
桶中心 = 论域上的分位
```

⇒ **“用实际值替换默认 keyword 上下限”确实存在过**（用户记忆成立）。

### B.2 但有三个限制

| # | 限制 | 后果 |
|---|---|---|
| 1 | **只换上界，不换下界** | 论域 = [表内默认下限, 设备上限]，**单边拉伸** |
| 2 | **只覆盖 14 组参数**（IP/IV/IL/PP/PV/MP/MBP/MSR/ML/VPTL/MEL） | **温度类（NT/BT/CT）、时间类（PT）、DDAM/DVAM/ET 等永远不覆盖** |
| 3 | 注释与代码矛盾：`inovance_service.py` L1219 写“范围不再按照机器设定参数，改为按照子规则库的工艺参数表”，但 L1222 仍调用 `read_machine_setting_para` | 注释与实现不一致（同 §4.4 词表那类问题） |

### B.3 迁移后果（现行 `molding-optima`）

- `RuleKeyword` **保留了对应字段**（`range_min/range_max` ← `all_range_*`；`action_range_min/max` ← `action_max_val`）
- 但**没有任何代码用设备量程覆盖 `range_max`** ⇒ **迁移遗漏（功能退化）**
- ⚠️ **为何一直没被发现**：keyword 种子默认值本来就是照设备量程填的（IV0=120、PP0=140…）⇒ **迁移前后论域数值相同**
- 真正暴露差异的场景：**换机台**（100 MPa 机 vs 350 MPa 机判成同一档）

### B.4 两条结论

1. **BT/NT 的 `[0,50]` 错位是继承自旧版的**，不是迁移丢失——温度类从来不在设备覆盖列表里（限制 #2）
2. **旧版的“实际值替换”也没解决“真实值只占论域 18%~32%”**——它解决的是**跨机台一致性**，不是**分位落点**
   ⇒ 与 §7.1 的 (a)/(b) 区分完全吻合，现在有代码级证据
3. ⇒ 新设计的“设备量程接入论域”**不是新功能，是恢复旧功能并补上它的三个缺陷**

#### 15.2 B —— 门控集合取错（修“门控不满足时规则反而激活”）

**病灶**（Mamdani `inference` L358 与 TSK `tsk_inference` L748 两处同源）：

```python
conditions = rule_matrix[i, rule_matrix[i] != 0]   # ❌ 取【隶属度非零】的列
```

`rule_matrix = connected_matrix * membership_degrees` ⇒ 某个门控的隶属度**恰为 0** 时，
该列被这一行表达式剔出 `conditions` ⇒ **该门控不参与乘积** ⇒
「门控不满足」被当成了「门控不存在」⇒ **规则反而激活**。

**修法**：改用**连接关系**取列 ——

```python
gate_cols = np.flatnonzero(self.connected_matrix[i])   # ✅ 取【连接到的列】
conditions = rule_matrix[i, gate_cols]
```

⇒ 隶属度 0 ⇒ 乘积含 0 ⇒ 激活度 0（门控不满足）。

#### 15.3 D —— TSK 主路径无激活度阈值

**病灶**：`MIN_ACTIVATION_THRESHOLD`（=0.01001）在 TSK 路径**零引用**；第四层（结论层）不看激活度地给每条规则出结论值 ⇒ 激活度≈0 的规则以 delta≈0 混进推荐列表（实测过 `BT conf=1.68e-282`、`CUSION conf=0.0`）。

**修法**（两处）：

```python
# 第三层后
activations_with_priority = new_activations * np.asarray(priority_array)
activations_with_priority[activations_with_priority < MIN_ACTIVATION_THRESHOLD] = 0.0

# 输出组装：跳过零权重规则，且三个列表同步构建（否则 zip 错位）
if activations_with_priority[i] <= 0:
    continue
```

⚠️ **阈值作用位置不可改**：必须卡**归一化 × priority 之后**的权重。
原始激活度里含缺陷门控的 `EPSILON=1e-7` 因子（缺陷字段不在 `process_parameter` 里），
卡原始值会把**所有含缺陷门控的规则**全干死。
