# 注射行程算法科学化改造设计

> 本文档记录将注射行程（`length_ratio` + `cushion_len`）从"按重量分档的经验玄学"重构为"基于物理推导 + 行业共识数据"的设计方案。

## 1. 设计背景

### 1.1 当前算法（经验玄学）

`initializer.py` 行 263-264 + 行 321-328 中：

```python
# 行 263-264：length_ratio 按总重量 W 三档硬分
total_len = injection_volume * 1000.0 / (HSO_PI * (screw_diameter ** 2) / 4)
length_ratio = 0.85 if total_weight <= 50 else (0.90 if total_weight <= 100 else 0.95)

# 行 321-328：cushion_len 按 W 二档硬分
weight_threshold = c_vps.get('cushion_threshold_weight', 120)
cushion_len = (
    c_vps.get('cushion_small', 10) if product_weight < weight_threshold
    else c_vps.get('cushion_large', 15)
)
vps_pos = cushion_len + (1 - length_ratio) * total_len
```

**核心问题**：

| 问题 | 表现 | 影响 |
|------|------|------|
| 数字来源不可追溯 | "为什么 W=50g 用 0.85？" → 答："经验" | 工艺师不敢用 |
| 泛化能力差 | 仅测试样本有效，新场景失效 | 新材料/大件风险高 |
| 物理意义模糊 | 50g/100g 分界无依据 | 调整无据可循 |
| 边界突变 | 49.9g→50.1g 跳变 5% | 工艺参数不稳定 |
| cushion_len 按 W 分档 | 小件 10mm，大件 15mm | 物理安全距离与 W 无关 |

### 1.2 优化目标

1. **数据基础升级**：从"几次试模经验"升级为"材料科学共识"
2. **物理推导替代经验拟合**：每个数字都能追溯到物理定律
3. **泛化能力提升**：适用于任意 W/D/材料组合
4. **保守兜底**：未识别材料自动采用最保守值

## 2. 两个问题的解耦定义

旧算法把"注射行程分配"和"保压安全余量"两个独立问题用同一个分档逻辑耦合在一起。新算法将它们**严格解耦**：

### 2.1 问题 A：length_ratio（注射 vs 保压行程分配）

```
本质：注射阶段与保压阶段的行程预算分配
取值依据：实际保压推进需求（基于物理推导）
反推公式：ratio = 1 - L_cushion_need / L_theory
```

### 2.2 问题 B：cushion_len（料垫长度设定）

```
本质：螺杆最终停止位置（VP 切换并完成补缩后的终点位置）
取值依据：纯机器物理参数（螺杆直径 D），与材料/制品无关
推导公式：cushion_len = max(ceil(D / 4), cushion_min_abs)
```

**物理依据**：
- 海天 8-12mm（推算 D=32-48mm）→ D/4 公式高度吻合
- Fanuc 10-15mm（推算 D=40-60mm）→ D/4 公式高度吻合
- 向上取整：安全优先（料垫宁多勿少），与工业实践一致
- 与 replenish_len 完全正交：replenish_len 只影响 vps_pos，不影响 cushion_len

**与原算法的关键区别**：
- 原算法：按产品重量二档硬分（小件 10mm，大件 15mm），无物理依据
- 现算法：D/4 推导，物理可解释、可验证、可扩展（未来按厂商微调 manufacturer_factor）

**关键洞察**：两个问题解耦后，各自走独立的推导路径，互不干扰。

## 3. 新算法核心（基于物理推导）

### 3.1 物理推导链

```
【起点：工艺目标】
保压阶段的物料补充量 ≥ 冷却收缩量 + 熔体压缩量
否则制品出现缩痕

【物理定律】
1. 质量守恒：补充体积 = 制品体积 × (收缩率 + 压缩率)
2. PVT 状态方程：熔体压缩由材料 PVT 数据决定
3. 圆柱几何：螺杆推进距离 = 补充体积 / 螺杆截面积

【反推 ratio】
ratio × L_theory = 注射行程 = 理论行程 - 保压推进距离
ratio = 1 - 保压推进距离 / 理论行程
```

### 3.2 完整计算公式

```python
# 步骤 1：理论行程（已有公式，不变）
L_theory = injection_volume * 1000.0 / (π × D² / 4)
# 其中 injection_volume = W / ρ（制品+流道总重量 / 熔体密度）

# 步骤 2：获取材料收缩率（3 级兜底）
shrink_rate, level = get_shrink_rate(polymer, c)

# 步骤 3：实际保压推进需求
pvt_compress = polymer.get('pvt_compress') or c.get('default_pvt_compress', 0.015)
A_screw = π × D² / 4
L_cushion_need = (shrink_rate + pvt_compress) × W / (ρ × A_screw) × 1000
# 不设下限：ratio 自然被 max(0, min(1, ...)) 钳制，小制品下 ratio 自然趋近 1.0

# 步骤 4：反推 ratio
ratio = max(0.0, min(1.0, 1 - L_cushion_need / L_theory))

# 步骤 5：cushion_len（料垫 = 螺杆终点位置，机器物理推导）
import math
cushion_min_abs = c_vps.get('cushion_min_abs', 5)
cushion_len = max(math.ceil(screw_diameter / 4), cushion_min_abs)  # D / 4 向上取整

# 步骤 6：VP 切换位置
vps_pos = cushion_len + L_cushion_need
```

## 4. 数据需求与 3 级兜底策略

### 4.1 数据需求（极简）

只需要 `Polymer.abbreviation` 字段（已有），其他字段都可通过兜底获取。

**不需要新增数据库字段**——`family` 从 `abbreviation` 自动解析。

### 4.2 3 级兜底数据流

```
【第 1 级】精确值（Polymer.shrink_rate 字段）
  ├─ 命中：直接使用
  └─ 适用：数据库已有完整材料物性数据
  
【第 2 级】按大类查表（family_shrink_map）
  ├─ 命中：使用大类典型值
  └─ 适用：能从 abbreviation 解析出 PP/PA/PC 等大类
  
【第 3 级】默认值（兜底）
  ├─ 命中：default_shrink_rate = 0.030
  └─ 适用：所有识别失败场景
```

### 4.3 材料大类典型收缩率（行业共识）

```json
{
  "family_shrink_map": {
    "PP": 0.020,
    "PE": 0.020,
    "PS": 0.005,
    "ABS": 0.006,
    "PC": 0.006,
    "PA": 0.022,
    "POM": 0.025,
    "PMMA": 0.005,
    "PET": 0.020,
    "PBT": 0.020
  }
}
```

**数据来源**：材料手册/教材/Moldflow 数据库的行业典型值。

### 4.4 兜底值选择依据

```
已知材料大类收缩率范围：0.3% ~ 2.5%
已知最大值：POM ≈ 2.5%
安全裕度：× 1.2
兜底值：default_shrink_rate = 0.030（3%）
```

**为什么 ×1.2**：即使材料识别错误（实际是 2.5% POM），兜底 3% 仍有 0.5% 裕度。

## 5. 保守兜底原则

### 5.1 决策优先级

```
短射（缺料）< 爆模（事故）

【原因】
- 短射：制品略偏小，可通过二次工艺调整补救
- 爆模：可能损坏模具（数万~数百万）、机器、极端时安全事故
- 因此兜底必须偏保守，宁可少打一点
```

### 5.2 兜底值定义

| 参数 | 兜底值 | 选取依据 |
|------|--------|---------|
| `default_shrink_rate` | 0.030 | 已知最大值 2.5% × 1.2 安全裕度 |
| `default_pvt_compress` | 0.015 | 熔体典型压缩率 |

### 5.3 未识别材料场景验证

设 D=50mm, ρ=1.0, default_shrink_rate=3%

| 场景 | L_cushion_need | ratio | 安全性 |
|------|---------------|-------|--------|
| W=30g, 未识别材料 | 0.69 mm | 1 - 0.69/15.3 = **0.955** | ✅ 正常 |
| W=100g, 未识别材料 | 2.29 mm | 1 - 2.29/50.9 = **0.955** | ✅ 正常 |
| W=200g, 未识别材料 | 4.58 mm | 1 - 4.58/101.9 = **0.955** | ✅ 正常 |
| W=500g, 未识别材料 | 11.46 mm | 1 - 11.46/254.6 = **0.955** | ✅ 正常 |
| W=1g, 未识别材料（极小件）| 0.028 mm | 1 - 0.028/0.80 = **0.965** | ✅ 合理 |
| W=10g, 未识别材料 | 0.28 mm | 1 - 0.28/7.96 = **0.965** | ✅ 合理 |

**所有场景下 ratio ∈ [0.955, 0.965]，物理合理，未识别材料略偏保守**。

## 6. 与原算法的对比

### 6.1 length_ratio 新旧对比（PP, D=40mm）

| W(g) | 旧 ratio | 新 ratio | 差异 | 旧 inj_len | 新 inj_len | 差值(mm) |
|------|---------|---------|------|----------|----------|---------|
| 5 | 0.85 | 0.965 | **+11.5%** | 3.38 | 3.84 | +0.46 |
| 30 | 0.85 | 0.965 | **+11.5%** | 20.29 | 23.04 | +2.75 |
| 50 | 0.85 | 0.965 | **+11.5%** | 33.82 | 38.40 | +4.58 |
| 80 | 0.90 | 0.965 | +6.5% | 57.30 | 61.43 | +4.14 |
| 100 | 0.90 | 0.965 | +6.5% | 71.62 | 76.79 | +5.17 |
| 150 | 0.95 | 0.965 | +1.5% | 113.40 | 115.19 | +1.79 |
| 200 | 0.95 | 0.965 | +1.5% | 151.20 | 153.58 | +2.39 |
| 500 | 0.95 | 0.965 | +1.5% | 377.99 | 383.96 | +5.97 |

**关键洞察**：

1. **旧公式**：ratio 按 W 三档硬分（W≤50 → 0.85, W≤100 → 0.90, W>100 → 0.95），假设“小件要多保压”
2. **新公式**：ratio 仅由材料物理决定（ratio = 1 - shrink_rate - pvt_compress），与 W 无关
3. **数学事实**：`replenish_len / total_len` 中的 W 约掉，ratio 只取决于材料
4. **小件偏差大**：W<50g 下旧公式偏低 11.5%，意味着注射行程短、保压补缩过多
5. **大件差异小**：W>100g 下新旧差异仅 1.5%，接近物理真相

**物理本质**：ratio 是材料常数，不是制品重量的函数。制品大小只影响绝对行程值，不影响 ratio 本身。旧公式的“按 W 分档”假设在物理上不成立。

### 6.2 总体对比

| 维度 | 原算法（玄学）| 新算法（科学）|
|------|--------------|--------------|
| 数据来源 | 几次试模 | 材料科学共识 |
| 可追溯性 | ❌ 来源不清 | ✅ 每个参数可追溯 |
| 可解释性 | ❌ "经验就是这样" | ✅ 每个数字都有物理意义 |
| 材料差异 | ❌ 不区分 PP/PA | ✅ PP/PA/PC 不同 |
| 泛化能力 | ❌ 仅测试样本 | ✅ 任意 W/D/材料 |
| ratio 决定因素 | W（制品重量） | 材料物理（收缩率 + PVT） |
| 调整路径 | 凭感觉调 | 修改 JSON 即可 |
| 失败归因 | 调参试错 | 哪个物理参数不准，一查就知 |
| 工艺师可信度 | "我不敢用" | "我敢用，且知道怎么调" |
| 数据库迁移 | 不需要 | 不需要（从 abbreviation 解析 family）|

### 7.2 推进步骤

1. **第一步**：算法逻辑改造（不依赖数据库迁移）
   - 改造 `initializer.py` 行 263-264 + 行 321-328
   - 实现 3 级兜底逻辑
   - 配置 `init_rules.json`

2. **第二步**：写测试用例
   - 覆盖典型材料大类（PP/PA/PC/ABS）
   - 覆盖典型重量范围（10g / 50g / 200g / 500g）
   - 对比新旧算法结果差异

3. **第三步**：内部验证
   - 选 2~3 个真实制品跑一遍
   - 工艺师 review 结果
   - 记录实际差异

4. **第四步**：灰度上线
   - 默认关闭新算法（开关控制）
   - 选 1 个机器/材料灰度开启
   - 收集生产反馈

5. **第五步**：逐步推广
   - 验证通过后，扩大范围
   - 持续收集反馈，微调大类典型值
