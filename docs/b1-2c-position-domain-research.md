# B1-2c 调研：位置类「产品充填量基准」可行性（2026-11-10）

> **状态**：调研完成并**已关闭**（未接线）。原候选路径 A/B/C/D 均不采用；后续由**路径 A′**（规则层实测反馈驱动）承接，见 [a5-shortshot-filling-rule-plan.md](a5-shortshot-filling-rule-plan.md)。
> **范围**：位置类参数（`IL0~IL5` / `ML0~ML3` / `MEL` / `VPTL`）的判级论域来源。
> **不做**：不改代码、不改规则库、不改 masterdata 数据。

---

## §0 一句话结论

**B1-2c 若定义为「把位置类判级基准从机台行程换成产品充填量需求」，实测证明它解决不了原始诉求**（短射 ⇒ 建议调大充填量）：规则库里**已经有**那 9 条 `MEL_add_*` 规则，但它们的前提是 `MEL_low`，而 `MEL_low` 在**所有**候选基准形态下的样本数都是 **0** ⇒ 规则恒失活。真正要改的是 **`MEL_low` 的判级依据**（绝对位置 → 相对产品需求的充填充足度），不是论域的「权威源」。

## §1 三条硬事实

### 1.1 事实一（数据层）：位置值是专家引擎按螺杆直径推导的，且**两套直径口径并存**

`ProcessParameter` 的位置列（`inj_pos_1..6` / `met_pos_1..4` / `met_end_pos`）不是手工录入，而是专家引擎按
`meter_posi = cushion_len(D) + total_len(weight, density, D)` 推导后落库（`param_source` 分布：`algorithm_init` 绝大多数，`system_inferred` 2 条，`manual_creation` 1 条）。

反解 `ML0 = cushion(D) + total_len(D)` 得到**隐含螺杆直径**：

| 隐含 D | 工况数 | 说明 |
|---|---|---|
| D ≈ 60.0 | **38** | masterdata **没有** D=60 的射台 |
| D ≈ 36.0 | 15 | 与当前 masterdata 射台一致 |
| D = 40.0 | 1 | cond 41，machine 11 |

**决定性证据**：`ProcessCondition.process_context_snapshot` 里记录的 `injection_unit.screw_diameter` = **60.0**，与位置值反推的 D **完全一致**（38 个工况）；而当前 masterdata `InjectionUnit`（machine 10 / unit 8）登记的是 **D=36 / stroke=200**。

⇒ **历史参数与当前机台登记已不同源**：参数是按 D=60 的机台算的，机台登记后来变成了 D=36。

masterdata 全表（4 台机 / 4 个射台）：

| unit | machine | unit_code | D | stroke | max_wt |
|---|---|---|---|---|---|
| 8 | 10 | IMM-DEMO-001-U1 | 36.0 | 200.0 | 240.0 |
| 2 | 11 | IMM-DEMO-002-U1 | 40.0 | 220.0 | 320.0 |
| 3 | 12 | IMM-DEMO-003-U1 | 36.0 | 200.0 | 240.0 |
| 4 | 12 | IMM-DEMO-003-U2 | 32.0 | 180.0 | 200.0 |

⇒ §6.4 记的「**80% 工况位置值超行程**」= 44/56（实测）**不是算法 bug，而是数据自相矛盾**：位置值按 D=60 算（行程需求 282~758mm），而登记机台是 D=36/stroke=200。

### 1.2 事实二（论域层）：换基准能提高可判率，但**提升主要来自「域变大」，不是产品语义**

判档口径沿用 §6.5（`FuzzyFeature([min,max], gauss, lvl)` 的 argmax；最大隶属度 < `GATE_TAU` ⇒ 判不出档，单列一桶计入分母）。
样本 = 真实库 56 工况各取最新一条 `ProcessParameter`；位置类参数 12 个（`IL0~IL5`/`ML0~ML3`/`MEL`/`VPTL`）。

候选形态：

| 代号 | 论域 | 语义 |
|---|---|---|
| C0 | `[0, masterdata 行程]` | **现状**（G6 守卫生效：当前值 > 行程 ⇒ 保留经验域） |
| C1 | `[0, meter_posi(快照同源 D)]` | 产品需求，**基准与参数同源** |
| C2 | `[0, meter_posi(masterdata D)]` | 产品需求，**基准与当前真机同源** |
| C2′ | `[0, 行程 × 4]` | **纯放大对照**（无产品语义） |
| C4 | `[0, max(行程, 产品需求)]` | 取大 |
| C3p | 值 = 当前值 / 产品需求，域 `[0,1.0]`/`[0,0.8]`/`[0,1.2]` | 充填充足度比例域 |

**整体可判率（12 参数 × 54 样本 = 648）**：

| 形态 | 可判率 |
|---|---|
| C0 现状 | **47.22%**（306/648） |
| C1 同源产品需求 | 55.40% |
| C2 当前机台产品需求 | 55.40% |
| **C2′ 纯放大 ×4** | **57.87%**（最高） |
| C4 取大 | 55.40% |
| C3p 比例域 | 100%（但分母只 375 —— 无值参数不计入） |

⇒ **C2′（纯放大，无任何产品语义）≥ C2（产品需求）** ⇒ 可判率提升**不是**产品语义带来的。

**区分度（同参数样本落同档的最大占比，越低越好）**：

| 参数 | C0 | C1 同源 | C2 产品需求 | C2′ 纯放大 |
|---|---|---|---|---|
| IL0 | 78% | **98%（恶化）** | 69% | 72% |
| IL1 | 78% | **98%（恶化）** | 69% | 78% |
| ML0 | 76% | **89%（恶化）** | 72% | 74% |
| MEL | 76% | 76% | 74% | 74% |

⇒ **C1（与参数同源的基准）必然恶化区分度**：基准 = 参数本身 ⇒ 恒判最高档 ⇒ 同质化。这是「不能用实测/推导值当基准」的又一处实证。

### 1.3 事实三（决定性）：规则**已存在**，但 `MEL_low` 恒不满足

规则库（`RuleMethod`，共 1646 条）中，「短射 ⇒ 调大充填量」的规则**存在且不止一条**（跨库重复）：

```
IF SHORTSHOT_low    AND MEL_low THEN MEL_add_2      # rule id 20 / 605 / 693 / 861 / 929 / 1002 / 1278
IF SHORTSHOT_medium AND MEL_low THEN MEL_add_3.0    # rule id 21 / 608 / 862 / 930 / 1005 / 1281 / 1549
IF SHORTSHOT_high   AND MEL_low THEN MEL_add_3.8    # rule id 22 / 611 / 863 / 931 / 1008 / 1284 / 1552
```

（另有 `MEL_add_3` / `MEL_add_5` 变体：rule id 831 / 1546 / 1284）

⇒ 规则**不缺**，缺的是 **`MEL_low` 这个前件永远不成立**。

**`MEL` 档位分布（n=54）**：

| 形态 | low | mid | high+ | 判不出 |
|---|---|---|---|---|
| **C0 现状（stroke 域）** | **0** | 2 | 41 | 11 |
| C1 同源产品需求 | **0** | 2 | 41 | 11 |
| C2 当前机台产品需求 | **0** | 40 | 3 | 11 |
| C4 取大 | **0** | 40 | 3 | 11 |
| C2′ 纯放大 ×4 | **10** | 40 | 4 | 0 |
| C3p 比例域 [0,1.0] | **0** | 38 | 16 | 0 |
| C3p 比例域 [0,0.8] | **0** | 38 | 16 | 0 |
| C3p 比例域 [0,1.2] | **0** | 38 | 16 | 0 |

⇒ **没有任何候选形态让 `MEL_low` 成立**（除 C2′ 纯放大能造出 10 个 low，但那是把域撑大造出来的假 low，无业务含义）。

**为什么比例域也救不了**：真实数据里 `ratio = MEL / 产品需求` 只有两个值 —— **1.0**（15 工况，参数与需求同源）与 **0.376**（38 工况，机台口径不同源）。在「**均分 3 档 + gauss**」内核下：

- 域 `[0,1.0]` ⇒ 桶中心 `[0, 0.5, 1.0]`，`σ = 0.25`；`ratio=0.383` ⇒ `μ_low = exp(-2.35) ≈ 0.095`，`μ_mid ≈ 0.80` ⇒ **判中档**
- 域 `[0,0.8]` ⇒ 中心 `[0, 0.4, 0.8]`，`σ = 0.2` ⇒ `μ_low ≈ 0.025`，`μ_mid ≈ 0.99` ⇒ **判中档**
- 域 `[0,1.2]` ⇒ 中心 `[0, 0.6, 1.2]`，`σ = 0.3` ⇒ `μ_low ≈ 0.196`，`μ_mid ≈ 0.55` ⇒ **判中档**

⇒ **「充填量只有需求的 37.6%」在当前内核的等分桶 + gauss 下必然判中档** ⇒ 要让它判低档，**必须改档位语义（非等分桶中心 / 换隶属度 / 独立阈值判据）**，这是内核级或规则级改动，**不是换论域来源能解决的**。

## §2 根因定位

| 层次 | 现状 | 与原始诉求的关系 |
|---|---|---|
| 规则库 | ✅ 已有 `SHORTSHOT_* AND MEL_low ⇒ MEL_add_*` | **不是问题所在** |
| 论域来源 | 位置类用 `stroke`（机台行程） | 换成产品需求**不解决问题**（实测） |
| **档位语义** | `MEL_low` = 「绝对位置小」（经验域 [0,200] 的低档） | ❌ **真正的阻塞点**：业务要的是「**充填量相对产品需求不足**」 |
| 数据 | 位置值与机台登记**不同源**（D=60 vs D=36） | 让 ratio 退化成两个离散值（1.0 / 0.376） |

⇒ **原始诉求（短射 ⇒ 建议调大充填量）要成立，需要同时满足**：
1. `MEL` 能被判成「低」⇒ 需改档位判据（相对产品需求的比例 / 独立阈值）；
2. 判据要能区分「够 / 不够」⇒ 需数据同源，否则比例只有两个离散值。

### 2.1 一个必须先说清的前提：参数由算法初始化 ⇒ 充填量恒「够」

位置值几乎全部是 `algorithm_init`（专家引擎按产品需求推导落库）⇒ **推导出来的位置值天然等于该件需求** ⇒ `ratio ≡ 1.0` ⇒ 「充填量不足」在「参数刚被算法初始化」的工况上**本来就不该出现**。

真正会出现「充填不足」的只有两种工况：

- **人工把位置调低了**（`manual_adjusted`）—— 生产常态（先按经验设，再试模微调）；
- **产品/材料改了但位置参数没重算**。

而当前 demo 数据里 `manual_adjusted` **一条都没有**（`param_source` 分布：`algorithm_init` 绝大多数、`system_inferred` 2 条、`manual_creation` 1 条）⇒

⇒ **路径 A 的效果在当前数据集上无法验证**。这一点必须写进验收口径：**A 属于「先接线、后用真实生产数据验证」**，不能用 demo 数据的区分度数字当验收证据（否则会得出「A 无效」的错误结论）。

## §3 候选路径（供拍板）

### 路径 A：引入「充填充足度」派生前件（规则层 + 小内核改动）

新增一个**独立判据**（不经等分模糊桶）：`ratio = 位置值 / 该件充填需求`，按**物理阈值**判档（如 `ratio < 0.6 ⇒ 充填不足`）。
规则库把 9 条规则的前件从 `MEL_low` 换成该派生前件。

- 代价：新增 1 个前件维度 + 改 9 条规则（跨 7+ 个库）+ 新增比例计算
- 收益：**直接命中原始诉求**；语义可解释（「充填量只有需求的 37.6%」）
- 风险：阈值 0.6 需业务确认；`SHORTSHOT` 与「充填不足」是否重复计分需确认

### 路径 B：改位置类档位语义（非等分桶中心 / 档位边界表）

`MEL`/`ML` 的档位边界由「等分 min/max」改为「按产品需求比例的边界表」（如 low=[0,0.6]、mid=[0.6,1.0]、high=[1.0,∞]）。

- 代价：内核桶中心算法变更（`bucket_centers`）+ `KeywordProfile`/`RuleKeyword` 规格扩展；**影响全部参数族**
- 风险：§6.5 的判档口径要重定义；C1 刚落地的高级论域模型要再改一次
- 收益：规则库**零改动**

### 路径 C：先修数据同源（机台口径）

让 masterdata 的机台/射台登记与历史参数同源（或按当前机台重算那 38 个工况的参数），使 `ratio` 变成连续分布而非两个离散值。

- 代价：数据修复（demo 数据）+ 可能重跑工艺参数初始化
- 收益：所有后续判据选择都不再错配；是路径 A/B 的**前提**
- 风险：demo 数据是否值得修未知；生产数据是否同样错配**未验证**

### 路径 D：放弃本线，转 §6.4 B1-2b + Q6

承认「短射先调充填量」在当前内核结构下不可达，先做「专家侧显式报出产品超机台能力」+ 规则库内容补齐。

## §5 状态更新：B1-2c 已关闭，转路径 A′

原 §5 的 4 个候选路径（**A** 派生前件 / **B** 改档位语义 / **C** 先修数据 / **D** 转线）**均不采用**。

原因：调研中确认「**计算充填量不能作为『够/不够』的判据**」——专家引擎的充填量是**一阶几何近似**（不含止逆环磨损、PVT 压缩、背压差异、实测密度偏差）；且 `MEL` 绝对值**主要由产品重量决定**，跨产品天然无意义。

⇒ 改走 **路径 A′**：把「充填量够不够」的判据从**计算充填量**换成**现场实测的短射缺陷反馈** —— 去掉 9 条死规则里的 `MEL_low` 前件，让实测缺陷直接驱动「增大充填量」。

**实施方案见**：[a5-shortshot-filling-rule-plan.md](a5-shortshot-filling-rule-plan.md)（其 §4 列出 4 项待拍板）。

**仍然有效、可供后续复用的调研结论**：

- §1.1 的**数据不同源**事实（D=60 vs D=36）—— 独立成立，是数据质量问题，价值仍待定；
- §1.2 的「**与参数同源的基准必然恶化区分度**」—— 「不能用实测/推导值当基准」的通用实证；
- §1.3 的「**等分 3 档 + gauss 下比例域必然判中档**」—— 内核级约束，后续若再走档位语义仍适用；
- §2.1 的「**参数由算法初始化 ⇒ 充填量恒『够』**」—— 对验收口径的约束仍成立。
