## 二、rules 必填项架构（重点新增）

### 2.1 背景

用户问："MoldForm 这种结构的必填项 rules 该如何设计？"

**现状分析**：
- MoldForm 顶层只有 `mold_no` 1 个 rule
- GatingSystemForm / CavityPanel 完全无 rules
- FormItem 类型支持 `rules?: any[]` 但实际未使用

**用户决策**：先实现架构，先确定流道类别必填，后续补充详细校验项。

### 2.2 整体架构

**核心原则**：FormItem 一站式声明 → FormFieldRenderer 透传 → 每个子表单独立 el-form + rules → 父级统一调 validate。

```
┌─ MoldForm (顶层) ─────────────────────────┐
│ formRef: { rules: { mold_no: [...] } }   │
│ ├─ 基本信息（el-form 1）                   │
│ └─ 其他参数（el-form 2）                   │
├─ 浇注系统：v-for GatingSystemForm           │
│   └─ gatingFormRefs[i].formRef            │ ← 子组件 expose
│       ├─ rules: { runner_type: [...] }   │ ← 流道类别必填
│       └─ validate() 由父级统一调 │
├─ 冷却系统：v-for CoolingSystemForm         │
│   └─ (未来加) formRef                     │
└─ 顶出系统：v-for EjectionSystemForm        │
    └─ (未来加) formRef                     │
```

### 2.3 三步实施

#### Step 1：扩展 FormItem 类型

[form-types.ts](../src/utils/form-types.ts) 增加 `required` 字段：

```ts
export interface FormItem {
  ...
  rules?: any[]      // 详细 Element Plus rules
  required?: boolean // 简化形式（红色星号）
}
```

**注意**：`required` 只是视觉提示，真正的验证需要 `rules: [{ required: true, message: '...', trigger: '...' }]`。

#### Step 2：FormFieldRenderer 透传

```vue
<el-form-item
  :label="item.label"
  :prop="item.prop"
  :label-width="labelWidth"
  :required="item.required"   <!-- 视觉必填 -->
  :rules="item.rules"          <!-- 验证逻辑 -->
>
```

#### Step 3：GatingSystemForm 加 rules + formRef + expose

```ts
const rules: FormRules = {
  runner_type: [
    { required: true, message: '请选择流道类别', trigger: 'change' },
  ],
}

const formRef = ref<FormInstance>()
defineExpose({ formRef })  // 暴露给父组件
```

basicItems 标记流道类别必填：

```diff

+ { label: '流道类别', prop: 'runner_type', type: 'select', options: runnerTypeOptions, required: true },
```

### 2.4 MoldForm 统一验证

## 三、allowCreate 字段引入

### 3.1 问题

用户指出："并不是所有的 select 都需要 allow-create，像注射次数这种就不允许用户自己创建。"

**根因**：FormFieldRenderer 的 el-select 硬编码 `allow-create`，所有 select 都允许自定义值。

### 3.2 方案：默认 true，仅关闭不允许的

#### FormItem 增加字段

```ts
export interface FormItem {
  ...
  /**
   * select 是否允许创建新选项（默认 true）
   * - false: 只能从 options 中选（如注射次数、模具结构等硬编码分类）
   * - true: 允许用户输入自定义值（如规格、备注等场景）
   */
  allowCreate?: boolean
}
```

#### FormFieldRenderer 透传

```diff
<el-select ...
- allow-create
+ :allow-create="item.allowCreate !== false"
>
```

**`item.allowCreate !== false`** —— 默认 `true`（向后兼容），显式设 `false` 才关闭。

#### 示例标注（注射次数）

```diff
- { label: '注射次数', prop: 'shot_count', type: 'select', options: shotCountOptions },
+ { label: '注射次数', prop: 'shot_count', type: 'select', options: shotCountOptions, allowCreate: false },
```

## 六、关键技术决策

### 6.1 为什么不把所有 rules 集中在 MoldForm 顶层？

**问题**：MoldForm 顶层 el-form 的 `:model` 是 `mold_info`，理论上可以验证嵌套路径如 `gating_systems.0.runner_type`。

**原因**：
- 子组件各自维护 el-form，符合 Element Plus 设计
- 避免路径冲突（不同 tab 的 form 路径相同）
- 子组件自己负责验证，封装性更好

### 6.2 为什么 required 不自动产生验证错误？

**Element Plus 行为**：
- `el-form-item.required=true` 仅显示红色星号
- 真正的验证需要 `rules: [{ required: true, ... }]`

**设计意图**：required 是声明意图（视觉），rules 是执行规则（验证）。

### 6.3 allowCreate 默认 true 的取舍

**优点**：现有功能 0 改动，向后兼容。

**缺点**：未来新增字段默认 `true`（可能误用）。

**结论**：低风险优先。如果后续发现太多误用，再考虑反向。

## 七、反思与教训

### 7.1 Vue 3 组件引用必须 import

Vue 3 template 编译不强制检查组件注册，未 import 的组件静默 fallback 到 HTML 元素（导致完全不显示）。

> 已记入 memory

### 7.2 el-alert 是页面级组件

表单字段上方用 el-alert 是反模式：
- 永久占用空间
- 信息密度低
- 与表单视觉风格冲突

**替代方案**：
- 按需提示：`el-tooltip`
- 永久提示：精简文案直接放在字段上方
- 强调提示：`el-form-item` 的 `error` slot

### 7.3 一次性脚本不要留在仓库

开发过程中的临时脚本（数据迁移、批量改样式等）完成后应立即删除，避免：
- 仓库臃肿
- 误导后续开发者
- 增加审查负担

**实践**：发现一次性脚本 → 立即删除 → 用 memory 记录关键决策。
