### 1.2 RuleMethodGraph 流程图重设计（components/RuleMethodGraph.vue）

#### ① 从笛卡尔积 → AND 聚合节点（最大改动）

**问题**：多个 condition 和 solution 时连线交叉混乱，视觉不直观。

**方案**：所有条件汇聚到中间 AND 节点，再由 AND 节点发散到所有动作。

```
之前（笛卡尔积，线交叉）：
[条件1] ─────╮
            ├──→ [动作1]
[条件2] ─────╯
[条件1] ─────╮
            ├──→ [动作2]
[条件2] ─────╯
... 交叉

之后（AND 聚合，无交叉）：
[条件1] ───╮
[条件2] ───┤──→ (AND) ──→ [动作1]
[条件3] ───╯        ╰──→ [动作2]
                  ╰──→ [动作3]
```

#### ② 修复 SVG ref 命名不一致（根本性 bug）

**症状**：模板用 `ref="coreRef"`，script 用 `const ruleCoreNode = ref(...)` —— `ruleCoreNode.value` 永远是 null，**没有连线**。

**修复**：统一为 `ref="ruleCoreNode"`。

> **教训**：Vue 3 模板 ref 必须与 script 中 ref 变量名**精确匹配**，否则 ref 静默返回 null，行为与设计意图不符。

#### ③ SVG marker 修复（箭头尺寸不受 stroke-width 影响）

**问题**：`markerUnits="strokeWidth"`（默认值）让箭头 = marker × stroke-width = 8×3 = **24px**——箭头巨大像匕首。

**修复**：

```scss
.el-drawer__title {
  ...
}

markers {
  markerUnits="userSpaceOnUse"   /* 关键：独立尺寸 */
  markerWidth="10"
  markerHeight="10"
  refX="9"
  refY="5"
}
```

#### ④ AND 节点改为完美正圆

**问题**：`border-radius: 36px` + 不对称尺寸（min-width: 80px, 高度 ~100px）导致圆头在左、椭圆在右。

**修复**：

```scss
.rule-core {
  width: 96px;
  height: 96px;
  border-radius: 50%;        /* 完美正圆 */
  background: linear-gradient(135deg, #409eff 0%, #67c23a 100%);
}
```

#### ⑤ 加大连线间距 + 偏移起止点

**问题**：三列间隙 16px，线条"贴脸"在节点边缘。

**修复**：

## 二、技术决策

### 2.1 流程图为什么用 AND 聚合节点？

| 方案 | 优点 | 缺点 |
|------|------|------|
| **笛卡尔积**（之前） | 直观表达"每条规则链" | n×m 条线，多条件多动作时严重交叉 |
| **AND 聚合节点**（选用）| 线不交叉，结构清晰 | "AND" 概念对非模糊控制领域用户需要解释 |
| **纯列表式** | 最简单 | 丢失"规则链"语义 |

**选用 AND 聚合的核心理由**：

1. **Mamdani 模糊规则教科书标准**：`IF (x1 is A1) AND (x2 is A2) THEN (y is B)` 中的 AND 天然适合作为"前提聚合点"
2. **视觉无交叉**：n 个条件 → 1 个 AND → m 个动作 = n+m 条线（之前 n×m 条）
3. **可扩展**：后续可加 OR 节点、嵌套聚合节点

### 2.2 Drawer Header 高度为什么保持 56px？

| 元素 | 高度 |
|------|------|
| padding-top + padding-bottom | 12 + 12 = 24px |
| 关闭按钮（决定 header 实际高度）| 32px |
| border-bottom | 1px |
| **总高** | **~56px** |

而 layout 的：
- `layout.vue` navbar：**56px**
- `sidebarLogo.vue` 侧边栏顶部：**56px**

**当前 drawer header（~56px）刚好和 layout 菜单栏（56px）一致**——这是视觉协调的关键。

> 用户反馈："drawer 和 layout 的菜单栏高度一致，看起来很协调"

**未来如需调整，应同时调整 layout 的 navbar / sidebarLogo**，不能单独改 drawer。

### 2.3 Drawer Header 装饰条为什么移除？

**逻辑链**：

1. Element Plus 默认 header 自带 `margin-bottom: 16px`（已用 `margin-bottom: 0` 覆盖）
2. 默认 header 自带 ~20px padding（已用 12px 偏低）
3. **如果再加左侧 3px 装饰条**，header 视觉上"撑得更满"，显得拥挤

**用户的判断**：

> "左侧的边线其实没必要，如果你把上下的 margin 去掉，那这个边线还可以，目前的 header 有点高"

**结论**：保持现状——**去掉装饰条 + 减小 padding**。如未来需要"贴边"风格，再**重新引入装饰条作为视觉锚点**。

## 七、反思与教训

### 7.1 Vue 3 ref 命名必须精确匹配

`ref="coreRef"` + `const ruleCoreNode = ref()` → `ruleCoreNode.value` 永远是 null。

**现象**：模板渲染没问题（核心节点显示正常），但所有依赖 ref 的逻辑（如 SVG path 计算）静默失败。

**教训**：

- template `ref` 属性值必须**精确等于** script 中的 ref 变量名
- 不像 `import` 错误会被编译警告，ref 命名错误是**完全静默**的
- 调试此类问题时，先在 script 里 `console.log(refName.value)` 验证 ref 是否拿到元素

> 已记入 memory（id=`Vue ref 命名一致性要求`）

### 7.2 不要"自作主张"破坏视觉协调

我曾建议缩小 drawer header 高度（更紧凑），但用户提醒：drawer header 必须和 layout 菜单栏（56px）保持一致。

**教训**：

- **跨组件的高度对齐** 是经过深思熟虑的设计，不要单方面打破
- 改动前先问"这会影响其它组件的对齐吗？"
- 即使方案"看起来更精致"，也不一定符合系统设计意图

> 已记入 memory（id=`Drawer header 与 layout 菜单栏高度一致性`）

### 7.3 SVG markerUnits 必须显式设置

`markerUnits` 默认是 `strokeWidth`——箭头尺寸 = marker × stroke-width。

**当 stroke-width 变化时，箭头会跟着放大缩小**，视觉上不可控。

**最佳实践**：永远显式设置 `markerUnits="userSpaceOnUse"`，让 marker 尺寸独立于 stroke-width。

> 已记入 memory（id=`SVG 连线与节点视觉规范`）

### 7.4 全局样式优先于组件局部样式

当一个 UI 模式（drawer header）有 **≥3 处使用** 时，应该：

1. **先抽全局样式**（`utilities/custom-*.scss`）
2. **再考虑组件局部增强**（特殊 drawer 加 :class 覆盖）

不要每个 drawer 都自己写一遍 header 样式。

> 已在 DRAWER_HEADER 中实现
